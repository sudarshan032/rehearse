## Part C. The top 3 in more detail

### 1. Backed (recommended)

- **Problem (my words):** "My resume isn't getting screened. Every rewrite adds buzzwords or numbers I can't prove, and tailoring it for each job takes me about an hour, so I apply to fewer jobs."
- **User:** me, and freshers / early-career engineers in India applying to many roles.
- **Core loop (day 1):** pick a project → hold the Wispr key and talk about it (English or Hinglish) → bullets appear, each number shown as **proved** (matches a source file) or **unproved** → paste a job description → keyword coverage + a tailored one-page resume.
- **Why voice:** telling the story out loud brings back the real details and numbers; typing bullets gives buzzwords. And it is exactly what interviewers ask: "walk me through it".
- **Real result plan (25–29 Oct):** run it for my 11 shortlisted jobs. Measure before (24 Oct: time to tailor one resume by hand, keyword coverage of my current resume per job) and after. Send real applications.
- **Edge items:** the proof check (rule-based, works with AI off); Hinglish in → English out on screen; "Walkthrough" interview mode only if time allows; a downloadable PDF.
- **Privacy:** my records stay on my laptop / in my browser; the demo uses a made-up fresher persona with sample records.
- **Learn:** ATS-style keyword matching, evidence linking, PDF generation, Hinglish handling.
- **Risk:** "another AI resume tool". Answer: the proof check and real numbers from my own 11 jobs. Interviews can't be measured by 29 Oct; we say that honestly.

### 2. CallCheck

As written in round 2: pin spoken notes to moments in a voice-bot call, turn them into test cases and prompt fixes, compare prompt versions. Best for skills and novelty; weakest on the 10-second test with non-engineer judges. Needs real test calls on most days from 25 to 29 Oct.

### 3. ShowYourWork

Spoken end-of-session recap + real commits/screenshots → a LinkedIn post that shows a real workflow (the Social prize rule). Most directly useful to the organisers; weakest on novelty because it sits next to the crowded write-up theme.

## Recommendation

**Backed.** It is the only idea that passes all five tests at once: everyone understands it, voice is the natural input,
the real numbers come from my own job hunt this week, WeMakeDevs' audience is exactly its users, and it gives Wispr's
India team the story they want. CallCheck is the stronger engineering project but a harder sell to these judges.
We can still use ShowYourWork's idea manually for our own posts.

# Round 4 (24 Oct): make Wispr the hero, not a dependency

**Siddhu's point (correct):** if Wispr only turns speech into text, any speech-to-text (or typing) can replace it, so it
can't be the hero. Backed would work the same with Claude + GitHub and a keyboard.

**What Wispr actually has** (checked 24 Oct, read-only):
- **Dictation history on your own Mac:** `flow.sqlite`, table `History`: every dictation with time, app (Terminal, Chrome, Slack…), URL, raw and polished text, word count, and your later edits. Wispr's MCP does *not* expose this ("does not have access to your dictations"), so it lives only on the laptop.
- **Notetaker + MCP server** (`https://api.wisprflow.ai/connect/mcp`): read-only access to meeting summaries, transcripts, tasks, Scratchpad notes and calendar events, signed in through the browser, no API key ([Wispr docs](https://docs.wisprflow.ai/articles/9551372685-connect-an-mcp-client-to-wispr-flow-remote-mcp-server)). Needs Notetaker + Cloud Sync; plan limits unclear (Pro month covers it).
- In the app: Command/Instruct mode, Styles, Snippets, Dictionary, Automations (feature flags in the local cache).

**Three levels of Wispr use:**
1. *Input only* (any speech-to-text works): what almost every entry does.
2. *Wispr-only features* (Hinglish clean-up, styles, command mode): visible but still swappable.
3. ***Wispr's data*** (your dictation history, Notetaker meetings, Scratchpad): **the product cannot exist without Wispr.** Nobody in the field does this yet.

**New test 6:** without Wispr, does the product still make sense? If yes, Wispr is not the hero.

# Round 5 (24 Oct): new scoring system, ideas re-done

**Siddhu's feedback:** Flow Ledger's raw history is too messy (four terminals, talking everywhere), so "make sense of
everything I said" won't work, and Backed + Ledger is out. Prompt Mirror, Interview Replay and Teach Wispr are good
ideas that the old scores undervalued.

**Why the old scores were wrong:** they were gut numbers, they rewarded "big" ideas and punished focused ones, and they
treated "Wispr used meaningfully" as "voice is natural", which every idea gets. That is why Backed (input only) scored
above Teach Wispr (built on Wispr itself).

## The new scoring system

**Step 1: five gates (pass/fail).** Fail one and the idea is out, whatever its score.

| Gate | Question |
|---|---|
| G1 Wispr is the hero | Without Wispr, would the product still make sense? (Must be **no**.) |
| G2 10-second test | Does a non-engineer judge get the problem and the user at once? |
| G3 Real number by 29 Oct | Can I measure a before/after on my own real material this week? |
| G4 Buildable | Core loop live in 1 day, finished in 5, free tiers only? |
| G5 Not crowded | Not an official example or a crowded theme in COMPETITION.md? |

**Step 2: score with fixed anchors**, weighted like the rubric. Each level has a written definition, so scores can be checked, not felt.

| Criterion (weight) | 10 | 7 | 4 |
|---|---|---|---|
| Real problem (30%) | I hit it every day, I can measure it on my own material this week, and the **judges have it themselves** | Weekly, measurable, clear user | Occasional, or hard to measure this week |
| Wispr meaningful (30%) | Built **on Wispr's own data or features**; its output goes back **into Wispr** (Dictionary, Snippets, Notetaker) | Needs a Wispr-only feature (Notetaker, Hinglish clean-up) | Voice is natural, but any speech-to-text works |
| Does it work (25%) | Public link, sample data, core works with no AI; **judges can try it on their own Wispr data in under a minute**, privately | Public link + sample data; needs a free AI tier behind a cache | Judges need their own account or setup to see anything |
| Demo clear (15%) | A visible before/after on screen in 30 s that the organisers would post | Clear, needs 15 s of explanation | Needs a lot of explaining |

**Step 3: tie-breakers (not weighted):** novelty in the field, what I learn, fit with my job hunt.

**Fact check behind the Wispr-data ideas** (read-only copy of my own history, counts only): 53 dictations, 6,909 words,
mostly Terminal (31) and Chrome (21); in **18** of them I edited Wispr's text after it was typed; Wispr itself made **306**
dictionary replacements; languages detected: English and **Telugu**; my Dictionary has 6 entries (2 snippets).
So the correction signal Teach Wispr needs really exists. (Meaning of each field still to be confirmed on day 1.)

**How judges can try it on their own data:** the page opens a *copy* of `flow.sqlite` **inside the browser**
(SQLite in WebAssembly). Nothing is uploaded. Without Wispr, a sample history loads. The judges work at Wispr and
WeMakeDevs, so most of them have Wispr installed.

### Telugu answer key: how to fix it (24 Oct)
- Recording playback confirmed: full sentence heard.
- Wispr does support Telugu dictation (one of its 104 languages) but accuracy on Siddhu's Telugu is weaker; Notetaker has no Telugu.
- Fix: Wispr's Telugu text is a **draft** answer key; the user corrects only the wrong words by typing them in English letters, converted live to Telugu (like easytelugutyping.com).
- easytelugutyping.com says it is "powered by Google" Input Tools and links the open-source `indic-transliteration` (Sanscript) library. Google Input Tools has no official public API, so we don't use it.
- Options: AI4Bharat **IndicXlit** (open-source model, handles loose spellings like Google; needs a small free server, e.g. a Hugging Face Space); **Sanscript.js** (open-source, runs in the browser, but needs exact spelling rules); or the phone/Mac Telugu keyboard (Gboard, macOS Telugu input). Plan: IndicXlit first, Sanscript as offline fallback.
- Page source check (24 Oct): easytelugutyping loads Google's old transliteration script (`jsapi` + `googleTranslation`, "powered by Google Input Tools") plus a fallback input tool. The site is a thin wrapper; the real work happens on Google's servers. Reverse engineering the page (e.g. with REA, github.com/morluto/rea, MIT) would only show this wrapper, not Google's model. Using Google's undocumented endpoint in our product is off-limits (not a supported public API). Use IndicXlit (same kind of small, fast transliteration model, not an LLM) and compare it against easytelugutyping by hand on a word list.
- Decision (24 Oct, Siddhu): use Google Input Tools for the Telugu fix box because it works best. Checked live: `inputtools.google.com/request?itc=te-t-i0-und&text=…` returns top-3 Telugu candidates ("vachaavu" and "vachavu" → వచ్చావు; "bagunnava" → బాగున్నావా). It is the backend of Google's Input Tools/Gboard typing, still running, but **not a documented public API** (no key, no terms, can stop any time). Use it as a helper only: per word on space, show the 3 choices, label "Telugu typing by Google Input Tools", and fall back to IndicXlit/Sanscript or the user's keyboard if it fails. Core scoring never depends on it.
